怎样看这些图

先看 3D |W| 和 channel RMS：数值是否集中在少数位置？再看 B32 误差热图：量化误差落在哪里？最后看固定输入的输出误差：这些 weight 误差有没有影响这份输入实际使用的方向？

每个方法的量化误差均相对自己的同基底 FP reference 计算。SpinQuant 使用 learned rotation，Row-scale VQ 和 MicroVQ 使用同一 frozen Smooth+H128 basis。3D 图使用共同的 128×512 weight 窗口和高度范围；全矩阵 RMS 曲线保留所有 input/output channels，并标出 CV。B32 是逐 output channel 的连续 32 个 input channels；SpinQuant 的实际量化 group 仍为 G128。

输出误差图最多展示 64×128，起点为 token 0、output channel 0；Video 实际显示 64×128，Action 为 32×128。汇总 NMSE 使用保存的全部 token rows 和完整 output width，并覆盖每层六个 case/step 上下文。

这是固定输入、bias-free FP32 矩阵乘法，输入不做 A4。SpinQuant INT4 与 VQ banks 都离线解码，因此这些图不能直接证明 native kernel 速度、action RMSE 或 closed-loop success 的改善。
