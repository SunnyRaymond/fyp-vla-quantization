# Resource facts and analytical estimates

Hardware: ASPIRE2A requested maximum 4 GPUs; the October 2, 2026 job log `experiment/reproduction/fastwam-smoke/artifacts/25658646.pbs101/job.log` reports NVIDIA A100-SXM4-40GB, total 40960 MiB per GPU. Root also queried PBS read-only this session: four-GPU vnode exposes 64 CPUs and approximately 440 GB host RAM. Availability at experiment time is not established. Four separate 40GB VRAM spaces are not a pooled allocation under DDP.

Analytical estimate only, not measured QAT: approximately 1B trainable BF16 ActionDiT parameters require about 2 GB parameter storage, 2 GB BF16 gradients, 8 GB FP32 Adam moments and optionally 4 GB FP32 master weights (12–16 GB). Frozen 5B BF16 video weights contribute approximately 10 GB; a separate BF16 1B action teacher adds approximately 2 GB. Text encoder/VAE, KV cache, action activations, fake-quant temporaries, allocator peaks and communication workspace are excluded. Sharding optimizer states/gradients or full parameters can reduce replicated storage, but its effectiveness requires a real training-memory gate.

The existing BF16 inference smoke is not evidence that a QAT backward pass fits. Teacher context/cache reuse is valid only for identical conditioning and a genuinely unchanged frozen context path. Shared-backbone baseline teachers may require a separate full-model copy; frozen parameters do not necessarily eliminate activation memory for differentiation through shared token interactions.

No measured samples/second, step time, training hours or total GPU-day campaign budget is available. The resource assessment must name sequence length, backward horizon, teacher evaluations/cache, trainable parameter count and sharding as cost drivers and remain conditional. There is no authorized GPU experiment or model/data download in this formulation request.

Native deployment is a separate requirement: fake quant on A100 is a training simulation, not low-bit GEMM speed evidence. Quantization format, excluded layers/KV precision, extra branches, exact packing and backend availability must be declared. A100 is not Blackwell and does not provide NVFP4 Tensor Core support; do not transfer a Blackwell FP4 benchmark or RTX4090 latency number to A100.

Action-only compression ceiling: ignoring scale metadata and excluded layers, a 5B BF16 video plus 1B BF16 action model has about 12 GB of core weights; quantizing only the 1B action weights to 4 bits leaves approximately 10 + 0.5 = 10.5 GB, only about 1.14x reduction of TOTAL core weight storage (the action subset itself is 4x smaller). This is a derived idealized bound, not measured full peak memory. Similarly overall query speed follows Amdahl's law with a measured action-time fraction; do not call a 4x action-layer storage reduction a 4x whole-WAM compression or acceleration. Shared-backbone extensions have a different storage accounting.
