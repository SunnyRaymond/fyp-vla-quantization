# WAM action-only QAT：模型接口来源摘录

核对日期：2026-10-03。此说明只记录接口与公开实现，不表示模型、数据或实验已在本机复现。FastWAM 来自本地 checkout `7faa71108368fbb3b6885649f112af607427a2d4`；LingBot-VA 与 Cosmos Policy 的引用指向当日读取的官方 `main`，它们是可变分支。

标记：**已核对**表示源码/配置直接写明；**推断**表示由所读代码结构推出；**未知**表示源码未足以确定。没有下载 checkpoint 或 dataset，也没有加载或运行模型。

## FastWAM：独立 ActionDiT，有可单独量化的主体

- **checkpoint 与权重关系 — 已核对：**本地 README 列出 HF checkpoint `yuanty/fastwam:libero_uncond_2cam224.pt` 和配套 `libero_uncond_2cam224_dataset_stats.json`。`configs/model/fastwam.yaml` 指向 `Wan-AI/Wan2.2-TI2V-5B` 视频专家，ActionDiT 为 30 层、hidden 1024、FFN 4096；`fastwam.py` 分别实例化 `video_expert` 和 `action_expert`，再交给 MoT，权重不是同一参数对象。ActionDiT 的预处理初始化从 Wan2.2 插值 backbone 载入部分权重，但 `action_encoder` 和 `head` 被明确跳过，运行时仍是独立 ActionDiT。源码结构可分别定位到本地 `configs/model/fastwam.yaml:1-56`、`src/fastwam/models/wan22/fastwam.py:136-159`、`src/fastwam/models/wan22/action_dit.py:32-98,149-232`。
- **动作采样输入与时间步 — 已核对：**`FastWAM.infer_action` 接收单张图像、prompt 或预计算文本 context、可选 proprio、action horizon；初始化高斯 action latent `[1, horizon, action_dim]`。它对输入图像做 VAE 编码，用首帧经 video expert 预填 per-layer K/V cache，然后按 action scheduler 的时间表只迭代 action expert。函数默认 20 个 inference steps；本地模型配置 action shift 为 1.0、1000 个训练 timestep。注意 README 对“原始发布 checkpoint”另要求 `EVALUATION.sigma_shift=5.0`，所以训练配置与发布权重的推理设定要绑定记录，不能混作一个版本。源码：`fastwam.py:979-1158`、`configs/model/fastwam.yaml:48-56`、`README.md:117-132`。
- **动作宽度与归一化 — 已核对：**本地 LIBERO 配置为 7 维动作（EEF pose 6 + gripper 1）、8 维 proprio；action normalization 使用 `min/max`，统计量可从训练集计算并保存。公开数据是 LeRobot 格式的 `yuanty/LIBERO-fastwam`；训练配置用 `RobotVideoDataset`，包含两路相机和 7D action。源码：`configs/data/libero_2cam.yaml:1-68`、`src/fastwam/datasets/lerobot/robot_video_dataset.py:28-120,214-216`、`README.md:54-75,276-300`。
- **FP video 是否可 detach — 已核对 + 推断：**video expert 对首帧生成的 K/V 被单独缓存，action expert 在每个去噪层显式读取这些缓存（`src/fastwam/models/wan22/mot.py:528-578`；`fastwam.py:1083-1155`）。因此冻结 video expert、保留原样 BF16 cache 并阻止其梯度，按当前 action 前向不会切断视觉条件；但每次新 observation 仍要做图像编码和 video cache prefill。适合把主要 ActionDiT 权重作为 action-only QAT 范围，不能把它描述为零成本 video path。

## LingBot-VA：当前公开 checkpoint 是 shared-backbone 版本

- **checkpoint 身份 — 已核对：**官方 README 将 `robbyant/lingbot-va-base`、`robbyant/lingbot-va-posttrain-robotwin`、`robbyant/lingbot-va-posttrain-libero-long` 均标为 shared backbone；同一 README 的公告说当时发布 shared-backbone 权重，并称 separated version 后续再发布。不要把论文/未来 separated-expert 版本当成本次可直接使用的公开 checkpoint。来源：[官方 README（News、Model Download）](https://github.com/Robbyant/lingbot-va/blob/main/README.md)。
- **权重分区 — 已核对：**当前 `wan_va/modules/model.py` 定义一个 `self.blocks` 堆栈；action 有自己的 `action_embedder`、action condition/time embedder 和 `action_proj_out`，训练时 video/action token 拼接后经过同一组 blocks，再拆分并分别输出。因此确有小型 action-specific 层，但主体 Transformer blocks 是共享权重。依据：[model.py（`WanTransformer3DModel.__init__`）](https://github.com/Robbyant/lingbot-va/blob/main/wan_va/modules/model.py)、[model.py（`forward_train`、`forward`）](https://github.com/Robbyant/lingbot-va/blob/main/wan_va/modules/model.py)。这是对公开 shared-backbone 代码的结论，不外推到 separated checkpoint。
- **动作接口 — 已核对：**LIBERO 配置的统一 action 表示为 30D，实际使用 `used_action_channel_ids=0..6` 七个通道；使用 quantile normalization，`q01/q99` 统计写在 LIBERO config。动作去噪步数 50、action SNR shift 0.05；配置还分别给 video 20 步与 video shift 5.0。来源：[va_libero_cfg.py（`va_libero_cfg`）](https://github.com/Robbyant/lingbot-va/blob/main/wan_va/configs/va_libero_cfg.py)。
- **数据与 loader — 已核对：**官方列出 `robbyant/robotwin-clean-and-aug-lerobot` 与 `robbyant/libero-long-lerobot` 数据集；README 说明自定义训练数据转换为 LeRobot、加 `action_config`、预提取 Wan2.2 VAE latent，再交 loader；30D 格式由左右 EEF/joints/grippers 组成，缺失维度补零。官方 loader 为 `wan_va/dataset/lerobot_latent_dataset.py` 中的 `LatentLeRobotDataset` / `MultiLatentLeRobotDataset`。来源：[README（Model Download、Custom Dataset Preparation）](https://github.com/Robbyant/lingbot-va/blob/main/README.md)、[loader（`LatentLeRobotDataset`、`MultiLatentLeRobotDataset`）](https://github.com/Robbyant/lingbot-va/blob/main/wan_va/dataset/lerobot_latent_dataset.py)。
- **FP video detach — 未知 / 不应假定：**公开 checkpoint 的 action 与 video 使用同一 blocks。源码显示可区分 token 与 action conditioning/head，但当前审阅的代码没有证明可用一个独立 BF16 video expert 预填特征、再让低比特 action expert 消费而前向保持等价。把共享 blocks 量化会同时改变两种 token 的计算；只量化 action embedding/head 虽可诚实称为 action-specific weights，但它不等于量化主体模型。

## Cosmos Policy：action 是共享 video denoiser 中的 token/latent 目标

- **checkpoint 身份与参数共享 — 已核对 / 推断：**官方 Quick Start 指向 `nvidia/Cosmos-Policy-LIBERO-Predict2-2B`，模型通过 `CosmosPolicyVideo2WorldModel`/`CosmosPolicyDiffusionModel` 扩展通用 video-to-world diffusion model。代码把 action chunk 写入视频 latent 张量指定的 action indices，再从同一 `model_pred.x0` 取 action 输出；没有独立的大型 action expert/head。因而主要 denoiser 权重与 video/state 预测共享。来源：[官方 README（项目介绍、Quick Start）](https://github.com/NVlabs/cosmos-policy)、[policy_text2world_model.py（`replace_latent_with_action_chunk`、`CosmosPolicyModelConfig`、`CosmosPolicyDiffusionModel`）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/models/policy_text2world_model.py)。
- **动作形状、采样与归一化 — 已核对：**LIBERO 数据 loader 读取 `[episode_len, 7]` float32 actions，默认开启 action normalization；官方 LIBERO inference 配置用 chunk size 16、action denoising 5 steps，并加载同一模型卡提供的 LIBERO stats 做 action/proprio scaling。模型代码的 action token 形状示例为 `[B, chunk_size, action_dim=7]`，替换到共同 latent 序列中。来源：[libero_dataset.py（`LIBERODataset`）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/datasets/libero_dataset.py)、[README（Quick Start 的 LIBERO 配置）](https://github.com/NVlabs/cosmos-policy)、[policy_text2world_model.py（`replace_latent_with_action_chunk`）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/models/policy_text2world_model.py)。
- **数据与 loader — 已核对：**README 链接公开 Models & Training Data；LIBERO 实验配置把 `LIBERODataset` 指向 `LIBERO-Cosmos-Policy/success_only`，chunk size 16，并启用 action normalization；loader 从 HDF5 读取 7D actions、利用统计量归一化。来源：[官方 README（Models & Training Data）](https://github.com/NVlabs/cosmos-policy)、[experiment configs（`libero_all_4_suites_dataset`）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/config/experiment/cosmos_policy_experiment_configs.py)、[libero_dataset.py（`LIBERODataset`）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/datasets/libero_dataset.py)。
- **动作专属量化与 detach — 已核对 + 推断：**模型支持按 action indices 做 loss mask/加权，但这是预测目标掩码，不是独立权重子集；同一个 video diffusion denoiser 仍处理共享时序 latent。来源：[policy_text2world_model.py（`compute_loss_with_epsilon_and_sigma`、action loss extraction）](https://github.com/NVlabs/cosmos-policy/blob/main/cosmos_policy/models/policy_text2world_model.py)。因此可严谨评估“action-only loss/QAT objective”或“只请求/输出动作的推理范围”，但把共享 denoiser 权重称为“action-only quantized weights”不准确。现有实现未证明可绕过/截断共享 video hidden states，同时保留相同 action 前向；输入 observation latent 的缓存与共享层内的 video-token activation 不应混为一谈。

## 对实验范围的直接含义

1. 可称为 **weight-scope action-only** 的首个平台是 FastWAM：仅量化独立 ActionDiT，video expert、VAE/text side 与提供视觉条件的 K/V 保持 BF16。固定相同 image/context/proprio、action noise、scheduler 与随机数，比较 BF16 与量化模型 action chunk。
2. LingBot-VA shared-backbone 与 Cosmos Policy 用于检验外推边界：它们有 action tokens、action heads 或 action loss masks，但主体权重共享。若量化共享 blocks，应称为 **action-targeted QAT of a shared backbone**；“只执行 action 输出”也不能自动解释为视频侧权重未量化。只有独立 action-specific modules 的参数才可称为 weight-scope action-only。
3. 以上源码没有证明 action fidelity 会转化为闭环成功率或原生 W4A8 kernel 延迟；这两项需分别评估。接口可执行性也不等于跨架构方法已验证。
