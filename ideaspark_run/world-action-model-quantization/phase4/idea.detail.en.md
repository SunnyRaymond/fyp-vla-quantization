# Causal Consequence Calibration for Quantized World Action Models

**Method.** One-Transition Consequence PTQ (OTC-PTQ)

## Motivation
**Problem framing.** For a coupled future-video/action WAM, calibration is not only about reproducing local tensors: a numerical intervention can change the predicted action chunk and, after the first action is executed, the next simulator observation. The concrete bottleneck is selecting which weight/activation sites should remain high precision when a local PTQ discrepancy does not consistently identify contact-transition consequences. The candidate therefore treats the full action chunk as an intermediate object and the one resulting control transition as the measurable boundary.

QuantWAMs (arxiv:2607.28405v1) already covers joint video/action sensitivity and closed-loop protection scheduling, and QuantWM (arxiv:2602.02110v1) covers weight/activation sensitivity with long-horizon latent planning. Earlier task-consequence work—VAML, Model Advantage / Value-Aware Model Learning, and Deep Task-Based Quantization—establishes that downstream consequence can guide targeting; SQIL establishes mission-critical-state protection through saliency-weighted QAT and action distillation. The gap is consequently narrower: OTC-PTQ asks whether a single numerical W/A intervention, with every other target site at FP16, can provide a reproducible one-control-transition proxy without claiming any of those broader principles as new.

**Why now.** The current Phase 0 frontier makes the boundary testable: QuantWAMs (arxiv:2607.28405v1) makes coupled video/action sensitivity and closed-loop protection explicit, QuantWM (arxiv:2602.02110v1) supplies a distinct latent rollout/planning sensitivity branch, and Fast-WAM (semanticscholar:b5be12ccbb037be57a1dbc03fbd43d379170055f) provides the named idm feasibility path without supplying a numerical PTQ consequence signal. Together with the stated RoboTwin 2.0/LIBERO manipulation split and Fast-WAM-only staged validation budget, this supports a small one-transition diagnostic now, provided the exact Optional IDM checkpoint identity is fixed in the pre-run manifest.

**Why prior work stopped.**
- `arxiv:2607.28405v1` (arXiv 2026): QuantWAMs measures joint video/action empirical-Fisher cross terms across block and denoising-step granularity and repairs fixed-count closed-loop protection schedules.
  - _Did not do_: It does not define the candidate's single-site W/A FP16-background intervention with paired full-action-chunk and next-observation $C_{r}$ from one executed control transition.
  - _Structural reason_: Its object is joint sensitivity and schedule repair, so it does not supply this one-site simulator counterfactual and one-transition numerical proxy.
- `arxiv:2602.02110v1` (arXiv 2026): QuantWM studies weight/activation PTQ sensitivity and long-horizon error in a DINO-WM latent planning setting.
  - _Did not do_: It does not instantiate a manipulation WAM coupled future-video/action denoiser with a single-site FP16-background intervention and $C_{r}$ from full-chunk/next-observation discrepancy.
  - _Structural reason_: Its latent rollout/planning estimand is different, leaving the coupled action-mediated transition measurement unspecified.
- `semanticscholar:b5be12ccbb037be57a1dbc03fbd43d379170055f` (arXiv 2026-03): Fast-WAM isolates video co-training from explicit future imagination and provides the named idm feasibility path for this branch.
  - _Did not do_: It does not provide a numerical PTQ consequence signal for one-site W/A protection allocation.
  - _Structural reason_: The missing mechanism is a paired simulator counterfactual that links a perturbed action chunk to the next observation after only the first action is executed.

**What changes when the gap closes.** If the gap closes, the field gains a bounded diagnostic for identifying when local PTQ discrepancy stops predicting one-control-transition consequence on contact states, complementing QuantWAMs' closed-loop protection branch and QuantWM's latent-planning sensitivity branch. It also becomes possible to test whether $a C_{r}-ranked$ schedule transfers to held-out contact-sensitive failures and next-observation deviation under the same precision budget, with permutation separating the consequence association from the quantizer and site-count controls. This would not establish task-loss identity, a full-horizon/replan marginal, joint-low-bit optimality, or a bytes/latency objective.

## Method
**Pipeline.** First freeze an exact pre-run manifest and make controller, RNG, history, and cache restoration executable for replayable calibration states. For each state, quantize one W/A site while every other target site remains FP16, generate paired full action chunks, execute only the first action, and compute the normalized $d_{a}$ and $d_{o}$ terms to obtain the episode-mean $C_{r}. Rank$ sites by $C_{r}$ and by local discrepancy under $B_{site}$, with B equivalent to $B_{site}$, then compare their bounded transfer on the stated held-out manipulation split. The contact-transition subset, $C_{r}$ permutation, and oracle simulator-state branch distinguish a consequence signal from local-score correlation or calibration noise.

### M1_background
*Provide replayable calibration states and exact version and configuration boundaries for paired measurement.*

1. **Freeze a replayable calibration state** (`S1`)
   - Create one immutable calibration record for each state before any paired measurement. Store $state_{id}$, task and episode identifiers, the starting observation and preprocessing record, simulator snapshot, controller state, ordered history, all random-number-generator streams, cache state, model/checkpoint identity, site-registry revision, and environment identity. Serialize one common baseline snapshot, then clone it into the FP16 reference branch and each candidate branch; restore each branch in a fixed order: model/checkpoint state, simulator state, controller state, history buffers, RNG streams, and cache contents plus keys and eviction metadata. The controller record must include policy hidden state, timestep, queued action chunk, and mode; the history record must preserve ordered observations, actions, rewards, and termination flags; the cache record must preserve scope and invalidation state. After restoration, replay the same baseline input and require the reference branch to reproduce the recorded observation and action output before measuring a site. The manifest must contain the exact Fast-WAM checkpoint identity and, when the Optional idm path is used, the exact Optional idm checkpoint identity and configuration. 【author decision: supply the immutable checkpoint identities and the exact-match fields for Fast-WAM and Optional idm; missing or mismatched identity must halt with no fallback artifact.】 The environment record must include CPU thread/process limits and the accelerator model and visible-memory class, explicitly distinguishing an 80GB-class run from an A100-40GB run. 【author decision: fix those execution-environment fields and the 80GB-class versus A100-40GB boundary in the manifest, including the memory-allocation policy.】 If any required identity or restoration check fails, halt before paired branch creation.
   - _Why:_ A paired consequence is interpretable only when both branches start from the same recoverable state; this preserves the version boundary instead of treating an unverified checkpoint as interchangeable.

### M2_one_transition_proxy
*Create the bounded single-site W/A intervention and compute the one-control-transition $C_{r}$ signal.*

2. **Apply a single-site W/A intervention** (`S2`)
   - Build a versioned site registry with stable $site_{id}$, module path or graph edge, tensor role (weight or activation), shape, dtype, capture point, and quantization granularity. For each candidate record, restore the S1 baseline, apply a mask containing exactly one $site_{id}$, quantize the selected weight tensor or intercept the selected activation at its registered graph edge, and leave every other target site at FP16. Record the operator parameters and verify that the mask changed only the selected site. The low-bit operator must be declared as either fake quantization or a real low-bit execution kernel, and the declared path must be used unchanged in calibration and held-out evaluation. 【author decision: choose and register $b_{lo}$, signedness, rounding, clipping, scale/zero-point, granularity, activation calibration data, and fake-quantization versus real-kernel mode; record backend/version and runtime verification when a real kernel is claimed.】 This is a single-site FP16-background intervention, not a joint-low-bit marginal or a joint-optimal schedule; QuantWM and QuantWAMs remain boundaries for their broader quantization scopes.

*Apply the low-bit operator only at numerical site r and keep every other target site at FP16.*
$$ \mathcal{Z}^{(r)}_j=\begin{cases}Q_{b_{\mathrm{lo}}}(\mathcal{Z}_r),&j=r\\\mathcal{Z}^{\mathrm{FP16}}_j,&j\ne r\end{cases} \tag{1} $$

   - _Why:_ This isolates the candidate's bounded site intervention and avoids treating joint coupling, joint-low-bit marginal effects, or joint optimality as new claims.
3. **Measure one-transition consequence** (`S3`)
   - From each restored reference/candidate pair, run inference once and capture the complete action chunks before executing any action. Execute only the first action from the restored state and capture the immediate next observation. Define $d_{a}(j,r)$ as the full-action-chunk MSE divided by $max(sigma_{a}^{2}, epsilon_{a}^{2})$, with $sigma_{a}^{2}$ the population variance over all scalar coordinates of FP16 full action chunks in $D_{cal}$. Define $d_{o}(j,r)$ as the mean per-pixel absolute next-observation difference divided by $max(sigma_{o}, epsilon_{o})$, with $sigma_{o}$ the calibration mean per-pixel standard deviation. Set $epsilon_{a}=epsilon_{o}=1e-3$ in normalized units, $lambda_{a}=lambda_{o}=1$ by default, preregister the $lambda_{a}/lambda_{o}$ sweep {0.5,1,2}, and aggregate $C_{r}$ as the episode mean with bootstrap intervals over complete episodes. Define the open-loop local surrogate $L_{jr}$ as the mean squared difference over all elements of the paired hook outputs and $L_{r}$ as its episode mean. The remaining open fields are the valid-element mask and observation preprocessing for the pixel term.【author decision: record both before held-out evaluation and apply them identically to both branches.】 Terminal, invalid, simulator-error, missing-observation, and variable-length rows also require one shared inclusion policy.【author decision: state whether each row is retained, masked, or excluded and record every exclusion reason.】

*Define $d_{a}$ as the full-action-chunk MSE divided by $max(sigma_{a}^{2}, epsilon_{a}^{2})$, and $d_{o}$ as the mean per-pixel absolute next-observation difference divided by $max(sigma_{o}, epsilon_{o})$. Use $epsilon_{a}=epsilon_{o}=1e-3$ in normalized units, $lambda_{a}=lambda_{o}=1$ by default with the preregistered sensitivity sweeps, and aggregate $C_{r}$ as the episode mean with bootstrap intervals over complete episodes.*
$$ d_a(j,r)=\frac{\operatorname{MSE}(\mathbf a_{jr},\mathbf a_{j0})}{\max(\sigma_a^2,\epsilon_a^2)},\quad d_o(j,r)=\frac{\operatorname{mean}_{\mathrm{pixel}}\left|\mathbf o_{(j+1)r}-\mathbf o_{(j+1)0}\right|}{\max(\sigma_o,\epsilon_o)},\quad C_r=\operatorname{mean}_{j\in D_{\mathrm{cal}}}\left(\lambda_a d_a(j,r)+\lambda_o d_o(j,r)\right) \tag{2} $$

   - _Why:_ This defines a one-control-transition proxy for action-mediated consequence while explicitly avoiding identity with task loss, a full-horizon/replan marginal, or a jointly-low-bit marginal.

### M3_matched_protection
*Use $C_{r}$ and local discrepancy to form matched protection schedules while keeping budget meanings separate.*

4. **Allocate protection at a matched budget** (`S4`)
   - Construct two deterministic protection schedules from the same site registry: one sorted by $C_{r}$ and one by local discrepancy. Define $B_{site}$, with B equivalent to $B_{site}$ everywhere in this method, as the nonnegative integer high-precision-site count recorded by the matched local-fidelity baseline in the preregistered run manifest. Protect exactly the $top-B_{site}$ sites, leave the rest at $b_{lo}$, resolve ties by registry order, and keep the primary comparison as a site-count budget. Record persistent weight bytes, peak live activation workspace, scale/copy overhead, and measured latency in a separate deployment-cost ledger. The numeric $B_{site}$ manifest entry remains open.【author decision: supply the nonnegative integer baseline site count and halt if it is missing or exceeds the registry size.】 Deployment bytes, activation workspace, scale/copy overhead, and latency remain a separate measurement protocol.【author decision: either provide that packing and timing protocol or mark those outcomes out of scope.】

*Select the top $B_{site}$ numerical sites by $C_{r}$; the site count is not a bytes or latency target.*
$$ \mathcal{P}_{C_r}(B_{\mathrm{site}})=\operatorname{TopB}_{\mathrm{site}}(\{(r,C_r):r\in\mathcal{R}\}) \tag{3} $$

   - _Why:_ The comparison tests whether the proxy changes protection choices at a matched precision budget, rather than introducing a storage or runtime objective.

### M4_validation
*Test contact-transition divergence and bounded transfer with permutation and oracle controls.*

5. **Run the bounded transfer and permutation check** (`S5`)
   - Use the immutable S1 manifest to run idm with sigma_shift_FW=1.0 and infer_action on the named held-out RoboTwin 2.0/LIBERO manipulation split. Hold the declared $b_{lo}$, B, $B_{site}$, preprocessing, reset protocol, controller restoration, and branch order fixed across the two schedules. Enumerate the held-out task IDs, episode and initial-state IDs, seeds, split membership, contact-transition predicate from simulator events, and task success/failure rule before inspecting results. 【author decision: supply the exact split and contact/failure definitions, including whether a contact transition is required before the first action or may occur after it.】 For each paired episode, restore the same initial state for both schedules, run the declared evaluation horizon, and record task outcome and the next-observation deviation with its aggregation window. 【author decision: pin the idm and infer_action entrypoint revisions and arguments, action horizon, termination rule, and whether next-observation deviation is first-transition-only or later-transition/full-episode; keep any latter summary separate from $C_{r}$.】 Build the permutation control by reassigning the recorded $C_{r}$ values across the same site IDs while preserving the score multiset, B, $B_{site}$, tie-breaking, and all other schedule rules. Use the specified oracle simulator-state branch only as a labeled positive control. 【author decision: specify the permutation seed and replicate/list, the oracle state source, the branch insertion point, and the comparison it controls; do not use it as a substitute for the real association.】 Interpret the result narrowly: $C_{r}$ remains a one-control-transition ranking proxy, while task failures and any full-horizon summaries are separate downstream outcomes rather than task loss or a full-horizon/replan marginal. QuantWM and QuantWAMs retain their broader WAM quantization boundaries; VAML, Model Advantage / Value-Aware Model Learning, Deep Task-Based Quantization, and SQIL retain prior-art ownership of broad consequence-, value-, task-, or critical-state-protection principles.

*Compare local-score versus $C_{r} rank$ correlation by state subset, with the predicted divergence concentrated on contact-transition states.*
$$ \Delta\rho=\rho_{\mathrm{noncontact}}-\rho_{\mathrm{contact}},\quad \rho_s=\operatorname{Spearman}(\{L_r\}_s,\{C_r\}_s) \tag{4} $$

   - _Why:_ The contact-transition subset and permutation are load-bearing mechanism tests: the candidate predicts ranking divergence and transfer for the real $C_{r}$ association, with its advantage disappearing after permutation; the oracle branch checks calibration noise.
