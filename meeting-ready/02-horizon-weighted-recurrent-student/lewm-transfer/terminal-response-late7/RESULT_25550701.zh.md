# terminal-response student + last7 teacher：配对 PushT 评估

日期：2026-09-25。PBS job `25550701.pbs101` 已完成：`job_state=F`、`Exit_status=0`、runner exit `0`。本次使用 `25549480.pbs101/terminal_response_step3000.pt`，在冻结的 50 个 PushT dataset-mode tasks 上比较新 student-only、每个 CEM batch 最后 7 轮使用 teacher 的 `late_teacher7`，以及 teacher-only。没有训练新模型或更换 checkpoint。

## 结果

| Arm | 成功 | Teacher cost calls | CUDA 同步的 CEM solve 总时间 |
|---|---:|---:|---:|
| 新 student-only | **2/50（4%）** | 0 | 36.80 s |
| 新 student + last7 teacher | **12/50（24%）** | 644 | 63.28 s |
| Teacher-only | **49/50（98%）** | 1,800 | 54.19 s |

last7 相对同一 student-only 多成功 **10/50**。逐任务配对表为：11 个仅 last7 成功、1 个仅 student 成功、1 个双方成功、37 个双方失败；50 个 source episodes 各贡献一个 task，双侧 exact paired sign-flip / McNemar `p=0.00634765625`。预先冻结的 `+5/50 且 p<0.05` 收益门通过。

完整推进门**未通过（有效实验中的 FAIL，而非 FAIL_CLOSED）**。last7 比 teacher-only 少成功 **37/50**，远超允许的 5 个；其 planner solve 时间比 teacher-only **慢 16.8%**，比值 `1.1678`，未达到 `≤0.70` 的速度门。虽然 teacher cost calls 是 teacher-only 的 `644/1800=35.8%`，调用次数减少没有在本次完整 CEM solve 测量中转化为加速。原因可能涉及混合路径的额外开销和不同的 rollout 轨迹，但本实验没有分离这些因素，不能指定单一原因。

## 有效性与解释范围

- Teacher-only 逐 task 成功向量与冻结 baseline `25534994.pbs101` **完全相同，49/50**；50 个 task key 与顺序一致，三臂共有 150 条结果。dataset-mode `World.evaluate`、goal offset 25、eval budget 50、CEM 30 轮 × 300 candidates / top30、seed 42 与此前 Stage 2 对齐。
- 每个 CEM batch 的路由、prepared observations、candidate shape、native RNG common prefix、数值有限性均通过检查。GPU 遥测每 5 秒写入 job log；本地日志有 112 个采样，间隔中位数 5.0 秒，最大利用率 78%，最大显存占用 643 MiB。
- `late_teacher7` 在这份很弱的 student 上仍带来真实的配对收益，说明最后 7 轮 teacher cost 对结果有用；但它远不能补回 teacher-only 的表现。该结果本身不能确定损失主要发生在 CEM 哪一轮，也不能证明某个训练 loss 是唯一原因。
- 历史的另一份 `treatment_step1000.pt` 在同一 50-task 方案上为 student-only `11/50`、late7 `26/50`、teacher-only `49/50`。新旧 checkpoint 的训练路线不同，因此 `2/50` 对 `11/50`、`12/50` 对 `26/50` 只是历史参照，不能作为单因素的 response-loss 因果效应。本次沿用既有 50-task cohort，是配对 follow-up，不是独立 untouched cohort。

## 判定与后续

**保留此 checkpoint 的 predictor-level NO-GO，不将它升级为 teacher replacement 或可用的加速方案。** 这次测试回答了用户指定的组合问题：last7 可以把新 student 从 2/50 拉到 12/50，但质量与速度均未达实用门槛。若要定位原因，下一步可先使用已保存的逐 solve 记录和既有 fresh-bank 结果，检查 teacher/student 的 score 与 elite 边界错误在不同阶段怎样传递；当前没有提交额外实验。
