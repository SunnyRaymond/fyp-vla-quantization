# LeWM PushT final-only teacher re-score 结果

## 判定

作业 `25536606.pbs101` 正常完成，PBS `Exit_status=0`，runner 与 `job_status` 均为 0，所有冻结 validity gates 通过。final-only round30 与 student-only 参照的**成功总数**相同，都是 **11/50**，但逐任务向量并不完全相同：两项 discordant pair 中 final-only 赢 1 项、student-only 赢 1 项。配对成功差为 `0`，exact two-sided McNemar `p=1.0`。因此主 gate 未通过：单次 round30 teacher 评分没有显示冻结的实用成功率增益。

两项不一致任务为：`task_index=14`（`row_index=941648`, `episode_idx=7572`, `start_step=116`）final-only 成功、student-only 失败；`task_index=37`（`row_index=1816073`, `episode_idx=14432`, `start_step=47`）结果相反。

late7 参照 `25536049.pbs101` 为 **25/50**，final-only 比该单次结果少 14 个成功，配对 `p=0.0013123`；这只能作为描述性机制参照。另一个有效 late7 作业 `25535873.pbs101` 是 **26/50**，故不能把 25/50 当成稳定或逐项固定的 late7 性能。Teacher-only 正控为 **49/50**，其向量与冻结 upstream-protocol-aligned baseline `25534994.pbs101` 完全一致。

按冻结解释，结果为 **`FINAL_ONLY_GAIN_NOT_DEMONSTRATED_MULTIROUND_REMAINS_HYPOTHESIS`**：单次末轮评分没有复现 late7 的观察收益，多轮 late feedback 仍值得作为解释保留，但当前结果没有证明它是因果机制。

## 有效性与运行证据

- 只运行一个新臂：每个实际 CEM `start_batch` 在 rounds 1–29 使用 treatment student cost，round 30 使用 teacher cost。总计 94 个真实 batch，teacher calls 恰为 94；每个 batch 的 30 轮 route flags 均匹配冻结排程。两个 solver calls 的 seed 均为 42，预 solve generator states 已逐项保存，candidate shape 均为 `[1, 300, 5, 10]`。
- 使用完全相同的 50 个 baseline task rows；HDF5 中 `episode_idx` 和 `step_idx` 均吻合，50 个 source episodes 唯一，没有缺失或重复 outcome。学生参照与 late7 参照使用相同 task key/order；teacher positive-control 向量与 baseline 完全一致。
- 六个 prepared observation keys 均存在，shape/dtype 与 finite/NaN 元数据已记录；当前一臂作业复用相同数据行、scalers、图像变换和 evaluator。早期 job 未保存原始 observation tensors，因此这里不声称跨作业 raw tensor 的逐位比较。
- Student checkpoint `25239551.pbs101/treatment_step1000.pt` provenance 与严格 loader 校验通过；dataset 与 official teacher 路径/大小符合 freeze。全部 outcomes、route flags、solver timings 和 summary 数值有限。
- Compute host 为 `x1000c2s1b0n0`，GPU 为 A100 40GB。`job.log` 有 63 个 5 秒间隔的 GPU 利用率/显存样本；PBS walltime 5:14，未触及内部 timeout 或 2 小时上限。
- 本作业 planner solve time 为 47.94 s，full evaluation 为 88.77 s，仅作本臂描述；不与先前多臂 job 直接比较绝对速度。该实验遵循 pinned upstream-protocol-aligned dataset mode，不是 verbatim `eval.py` 或 random-reset PushT。

## 下一步

目前证据不支持通过“只在 final CEM round 加一次 teacher call”来恢复 student-only 成功率。此前 K-screening、固定 observation CEM candidate-tail distillation 与 pairwise-ranking 也未通过冻结 predictor/planner gate；继续扩展这些 recipe 信息量不高。下一条值得另行设计的路线是**真正 student-induced state 的 teacher-label aggregation**：先以当前 student planner 在 simulator 中生成有界 closed-loop 轨迹，再让 teacher 对这些已访问状态/候选提供监督，检验训练分布是否需要跟随 student 的 planner 状态分布。它不同于重复拟合固定 observation 的 candidate tail；但需要新的 simulator reset/rollout freeze 和单独 validity gate，本结果不自动授权提交该训练作业。

后续阅读可从 de Boer et al. 的 [Cross-Entropy Method tutorial](https://doi.org/10.1007/s10479-005-5724-z) 复习 elite updates 如何逐轮改变采样分布；若继续考虑 student-induced data aggregation，可读 Ross et al. 的 [DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)。DAgger 用于 LeWM planner-cost targets 是方法迁移，不能当作已有验证结论。
