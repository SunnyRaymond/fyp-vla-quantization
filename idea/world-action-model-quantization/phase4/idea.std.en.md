# Causal Consequence Calibration for Quantized World Action Models

**Method.** One-Transition Consequence PTQ (OTC-PTQ)

## Motivation
For a coupled future-video/action World Action Model (WAM), post-training quantization (PTQ) calibration is not only about reproducing local tensor values. A numerical intervention can change the predicted full action chunk; after the first action is executed, it can also change the simulator's next observation. The practical bottleneck is deciding which weight/activation (W/A) sites should stay at high precision when a local PTQ discrepancy does not consistently identify contact-transition consequences. OTC-PTQ therefore treats the full action chunk as an intermediate object and the one resulting control transition as the measurable boundary.

The current Phase 0 frontier makes this boundary testable. QuantWAMs (arxiv:2607.28405v1) makes joint video/action sensitivity and closed-loop protection explicit, QuantWM (arxiv:2602.02110v1) provides a distinct latent rollout/planning sensitivity branch, and Fast-WAM provides the named idm feasibility path without providing a numerical PTQ consequence signal. Together with the stated RoboTwin 2.0/LIBERO manipulation split and Fast-WAM-only staged validation budget, this supports a small one-transition diagnostic, provided the exact Optional IDM checkpoint identity is fixed in the pre-run manifest.

Several adjacent directions are already covered. QuantWAMs measures joint video/action sensitivity and repairs closed-loop protection schedules; QuantWM studies weight/activation PTQ sensitivity and long-horizon latent planning; and Fast-WAM does not provide a numerical PTQ consequence signal for one-site W/A protection allocation. Earlier task-consequence work—VAML, Model Advantage / Value-Aware Model Learning, and Deep Task-Based Quantization—already shows that downstream consequence can guide targeting, while SQIL covers critical-state protection through saliency-weighted QAT and action distillation. The narrower gap is whether one numerical W/A intervention, with every other target site at FP16, can provide a reproducible one-control-transition proxy from paired full-action-chunk and next-observation discrepancy. OTC-PTQ does not claim those broader downstream-consequence or critical-state-targeting principles as new.

If this gap closes, the field gains a bounded diagnostic for identifying when local PTQ discrepancy stops predicting one-control-transition consequence on contact states. It complements QuantWAMs' closed-loop protection branch and QuantWM's latent-planning sensitivity branch. It also enables a test of whether $a C_{r}-ranked$ schedule transfers to held-out contact-sensitive failures and next-observation deviation under the same precision budget, with permutation separating the consequence association from quantizer and site-count controls. This would not establish task-loss identity, a full-horizon/replan marginal, joint-low-bit optimality, or a bytes/latency objective.

## Method
### M1_background
*Provide replayable calibration states and exact version and configuration boundaries for paired measurement.*

1. Create one immutable calibration record for each state before any paired measurement. Store the state identifier, task and episode identifiers, starting observation and preprocessing record, simulator snapshot, controller state, ordered history, all random-number-generator (RNG) streams, cache state, model/checkpoint identity, site-registry revision, and environment identity. Serialize one common baseline snapshot, then clone it into the 16-bit floating-point (FP16) reference branch and one candidate branch per site; restore each branch in a fixed order: model/checkpoint state, simulator state, controller state, history buffers, RNG streams, and cache contents with keys and invalidation metadata. The controller record must include policy hidden state, timestep, queued action chunk, and mode; the history record must preserve ordered observations, actions, rewards, and termination flags; the cache record must preserve scope and invalidation state. After restoration, replay the same baseline input and require the reference branch to reproduce the recorded observation and action output before measuring a site. Store the exact Fast-WAM checkpoint identity and, when Optional idm is used, the exact Optional idm checkpoint identity and configuration in the manifest. 【author decision: supply the immutable Fast-WAM and Optional idm checkpoint identities and exact-match fields; a missing or mismatched identity must halt with no fallback artifact.】 Store the central processing unit (CPU) thread/process limits and accelerator model and visible-memory class as environment fields, explicitly distinguishing an 80GB-class run from an A100-40GB run. 【author decision: fix those environment fields and the 80GB-class versus A100-40GB boundary in the manifest, including the memory-allocation policy.】 If any required identity or restoration check fails, halt before creating paired branches.
   - _Why:_ Both branches are interpretable as a paired consequence only when they start from the same recoverable state. This preserves the version boundary instead of treating an unverified checkpoint as interchangeable.

### M2_one_transition_proxy
*Create the bounded single-site W/A intervention and compute the one-control-transition $C_{r}$ signal.*

2. Build a versioned site registry for weight/activation (W/A) sites with a stable $site_{id}$, module path or graph edge, tensor shape, data type, capture point, and quantization granularity. For each candidate, restore the step 1 (Create one immutable $calibration\dots )$ baseline, apply a mask containing exactly one $site_{id}$, quantize the selected weight tensor or intercept the selected activation at its registered graph edge, and leave every other target site at 16-bit floating-point (FP16). Record the operator parameters and verify that the mask changed only the selected site. Declare the low-bit operator as either fake quantization or a real low-bit execution kernel, and use that declared path unchanged in calibration and held-out evaluation. 【author decision: choose and register $b_{lo}$, signedness, rounding, clipping, scale/zero-point, granularity, activation calibration data, and fake-quantization versus real-kernel mode; record backend/version and runtime verification when a real kernel is claimed.】 This is a single-site FP16-background intervention, not a joint-low-bit marginal or joint-optimal schedule; QuantWM and QuantWAMs remain prior-art boundaries for their broader quantization scopes.

*Apply the low-bit operator only at numerical site r and keep every other target site at FP16.*
$$ \mathcal{Z}^{(r)}_j=\begin{cases}Q_{b_{\mathrm{lo}}}(\mathcal{Z}_r),&j=r\\\mathcal{Z}^{\mathrm{FP16}}_j,&j\ne r\end{cases} \tag{1} $$

   - _Why:_ This isolates the bounded single-site intervention and avoids treating joint coupling, joint-low-bit marginal effects, or joint optimality as new claims.
3. Run the reference and one-site branch from matched restored states. Save each complete action chunk before any action is executed, including its time length, action ordering, valid-step mask, and data type. Restore the state separately for each branch, execute only the first action, and save the immediate next observation and terminal or simulator-error flags. Define $d_{a}(j,r)$ as the full-action-chunk mean-squared error divided by $max(sigma_{a}^{2}, epsilon_{a}^{2})$, where $sigma_{a}^{2}$ is the population variance over all scalar coordinates of FP16 full action chunks in $D_{cal}$. Define $d_{o}(j,r)$ as the mean per-pixel absolute next-observation difference divided by $max(sigma_{o}, epsilon_{o})$, where $sigma_{o}$ is the calibration mean per-pixel standard deviation. Use $epsilon_{a}=epsilon_{o}=1e-3$ in normalized units and $lambda_{a}=lambda_{o}=1$ by default, preregister $a lambda_{a}/lambda_{o}$ sweep over {0.5,1,2}, and set $C_{r}$ to the episode mean of $lambda_{a} d_{a}+lambda_{o} d_{o}$ with bootstrap intervals over complete episodes. Define the open-loop local surrogate $L_{jr}$ as the mean squared difference over all elements of the paired hook outputs and $L_{r}$ as the episode mean. The remaining open fields are the valid-element mask, observation preprocessing, and one identical inclusion policy for terminal, invalid, simulator-error, missing-observation, and variable-length rows. $C_{r}$ remains a one-control-transition proxy, not task loss, a later rollout/replan marginal, or a jointly-low-bit marginal. The remaining open fields are the valid-element mask and observation preprocessing for the pixel term.【author decision: record both before held-out evaluation and apply them identically to both branches.】 Terminal, invalid, simulator-error, missing-observation, and variable-length rows also require one shared inclusion policy.【author decision: state whether each row is retained, masked, or excluded and record every exclusion reason.】

*Define $d_{a}$ as the full-action-chunk MSE divided by $max(sigma_{a}^{2}, epsilon_{a}^{2})$, and $d_{o}$ as the mean per-pixel absolute next-observation difference divided by $max(sigma_{o}, epsilon_{o})$. Use $epsilon_{a}=epsilon_{o}=1e-3$ in normalized units, $lambda_{a}=lambda_{o}=1$ by default with the preregistered sensitivity sweeps, and aggregate $C_{r}$ as the episode mean with bootstrap intervals over complete episodes.*
$$ d_a(j,r)=\frac{\operatorname{MSE}(\mathbf a_{jr},\mathbf a_{j0})}{\max(\sigma_a^2,\epsilon_a^2)},\quad d_o(j,r)=\frac{\operatorname{mean}_{\mathrm{pixel}}\left|\mathbf o_{(j+1)r}-\mathbf o_{(j+1)0}\right|}{\max(\sigma_o,\epsilon_o)},\quad C_r=\operatorname{mean}_{j\in D_{\mathrm{cal}}}\left(\lambda_a d_a(j,r)+\lambda_o d_o(j,r)\right) \tag{2} $$

   - _Why:_ This defines a one-control-transition proxy for action-mediated consequence. $C_{r}$ is not task loss, a full-horizon/replan marginal, or a jointly-low-bit marginal.

### M3_matched_protection
*Use $C_{r}$ and local discrepancy to form matched protection schedules while keeping budget meanings separate.*

4. Construct two deterministic protection schedules from the same site registry: one sorted by $C_{r}$ and one by local discrepancy. Define $B_{site}$, with B equivalent to $B_{site}$ everywhere in this method, as the nonnegative integer high-precision-site count recorded by the matched local-fidelity baseline in the preregistered run manifest. Sort descending and break ties by registry order, protect exactly the $top-B_{site}$ sites at FP16, and leave all other target sites at $b_{lo}$. The numeric $B_{site}$ and its manifest entry remain open inputs; halt if the entry is missing or $B_{site}$ exceeds the registered site count. Record persistent weight bytes including copies and scales, peak live activation workspace under the real kernel, scale/copy overhead, and measured latency separately; these quantities are not substituted for the site-count budget. The numeric $B_{site}$ manifest entry remains open.【author decision: supply the nonnegative integer baseline site count and halt if it is missing or exceeds the registry size.】 Deployment bytes, activation workspace, scale/copy overhead, and latency remain a separate measurement protocol.【author decision: either provide that packing and timing protocol or mark those outcomes out of scope.】

*Select the top $B_{site}$ numerical sites by $C_{r}$; the site count is not a bytes or latency target.*
$$ \mathcal{P}_{C_r}(B_{\mathrm{site}})=\operatorname{TopB}_{\mathrm{site}}(\{(r,C_r):r\in\mathcal{R}\}) \tag{3} $$

   - _Why:_ The comparison tests whether the proxy changes protection choices at a matched precision budget, rather than introducing a storage or runtime objective.

### M4_validation
*Test contact-transition divergence and bounded transfer with permutation and oracle controls.*

5. Use the immutable step 1 (Create one immutable $calibration\dots )$ manifest to run the idm entrypoint with sigma_shift_FW=1.0 and infer_action on the named held-out RoboTwin 2.0/LIBERO manipulation split. Use the same declared $b_{lo}$, B, $B_{site}$, preprocessing, reset procedure, controller restoration, and branch order for the two schedules. List the held-out task identifiers, episode and initial-state identifiers, seeds, split membership, simulator-event contact predicate, and task success/failure rule before inspecting results. 【author decision: provide the exact split and contact/failure definitions, including whether contact must occur before the first action or may occur after it.】 For each paired episode, restore the same initial state for both schedules, run the declared evaluation horizon, and record task outcome and next-observation deviation with its aggregation window. 【author decision: pin the idm and infer_action entrypoint revisions and arguments, action horizon, termination rule, and whether next-observation deviation is first-transition-only or later-transition/full-episode; keep any later summary separate from $C_{r}$.】 Create the permutation control by reassigning the recorded $C_{r}$ values across the same site identifiers while preserving the score multiset, B, $B_{site}$, tie-breaking, and every other schedule rule. Run the specified oracle simulator-state branch only as a labeled positive-control branch. 【author decision: specify the permutation seed and replicate/list, oracle state source, branch insertion point, and controlled comparison; do not use the oracle as a substitute for the real association.】 Keep the interpretation bounded: $C_{r}$ is a one-control-transition ranking proxy, while task failures and full-horizon summaries are separate downstream outcomes, not task loss or a full-horizon/replan marginal. QuantWM and QuantWAMs retain their broader world action model (WAM) quantization boundaries; VAML, Model Advantage / Value-Aware Model Learning, Deep Task-Based Quantization, and SQIL retain prior-art ownership of broad consequence-, value-, task-, or critical-state-protection principles.

*Compare local-score versus $C_{r} rank$ correlation by state subset, with the predicted divergence concentrated on contact-transition states.*
$$ \Delta\rho=\rho_{\mathrm{noncontact}}-\rho_{\mathrm{contact}},\quad \rho_s=\operatorname{Spearman}(\{L_r\}_s,\{C_r\}_s) \tag{4} $$

   - _Why:_ The contact-transition subset and permutation are mechanism tests: the candidate predicts ranking divergence and transfer for the real $C_{r}$ association, with the advantage disappearing after permutation. The oracle branch checks calibration noise.
